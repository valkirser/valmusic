# Build and publish ValMusic

ValMusic is a Tauri 2 desktop app. It must be built on the target operating system: use Windows
for Windows installers, macOS for the Mac app, and Linux for Linux packages. For the native
libmpv prerequisites and platform-specific caveats, see [BUILD-PLATFORMS.md](BUILD-PLATFORMS.md).
The bundle identifier intentionally remains `com.limusic.desktop`, which makes ValMusic reuse
Limusic's Tauri app-data/config directory for settings and login state.

## Build locally

Install Rust stable, Node.js, pnpm, and the platform prerequisites in `BUILD-PLATFORMS.md`. From
the repository root:

```sh
cd ui
pnpm install --frozen-lockfile
pnpm build
cd ..
cargo install tauri-cli --version '^2'
cargo tauri build
```

Bundles are written under `target/release/bundle/`. The platform config chooses these bundle types:

- Windows: NSIS setup executable and MSI.
- macOS: `.app` and drag-install `.dmg`.
- Linux: AppImage, `.deb`, and `.rpm` where the host supports them.

On Linux, use the pinned Ubuntu 24.04 release runner for distributable AppImage and Debian packages;
the system glibc version on a newer build host can make them fail on older distributions.

## FFmpeg and audio conversion

ValMusic bundles FFmpeg for converted downloads. The release workflows fetch FFmpeg with
`AnimMouse/setup-ffmpeg`; local builds automatically copy `ffmpeg` from `PATH` into
`src-tauri/resources/ffmpeg/` before Tauri packages the app. To choose a specific executable, set
`FFMPEG_PATH` before building (for example, in PowerShell: `$env:FFMPEG_PATH = 'C:\tools\ffmpeg\bin\ffmpeg.exe'`).
Original-format downloads do not need FFmpeg; MP3, FLAC, WAV, M4A, and Opus conversion uses the
bundled copy. On Windows, FFmpeg runs without opening a terminal window.

## Create GitHub release installers

Before pushing, point this checkout's `origin` remote at your fork and verify it:

```sh
git remote set-url origin https://github.com/OWNER/ValMusic.git
git remote -v
```

Then push the source changes and version tag to **your ValMusic fork**, and build each platform
on its own OS. The copied `scripts/release.sh` is the upstream multi-platform publisher and needs
fork-specific artifact names and updater configuration before it can be used. It now requires
`VALMUSIC_GITHUB_REPO=OWNER/ValMusic` and refuses Limusic's upstream name.
The copied release workflows also have upstream-specific artifact checks and need fork-specific
updater/signing configuration before they can publish automatically.

After building on each machine, create the release once and upload the other platform's installers
to that same release. Replace `OWNER/ValMusic` with the actual owner and repository name:

```sh
git tag v1.0.0
git push origin v1.0.0
gh release create v1.0.0 --repo OWNER/ValMusic --title "ValMusic 1.0.0" --generate-notes
```

Upload the generated files from each platform, replacing the path placeholders with actual files
from the bundle directory:

```sh
gh release upload v1.0.0 PATH-TO-WINDOWS-SETUP.exe PATH-TO-WINDOWS.msi --repo OWNER/ValMusic
gh release upload v1.0.0 PATH-TO-MACOS.dmg --repo OWNER/ValMusic
gh release upload v1.0.0 PATH-TO-LINUX.AppImage PATH-TO-LINUX.deb PATH-TO-LINUX.rpm --repo OWNER/ValMusic
```

Use the filenames actually generated by Tauri; version and architecture are part of each name.
Upload one file at a time if needed. For automatic in-app updates, the release also needs Tauri's
signed updater artifacts and a `latest.json` manifest. Ordinary installers attached to a GitHub
release do not create those automatically.

The updater endpoint already points to `https://github.com/valkirser/valmusic`. The configured
public key is still the inherited Limusic key, so create a new key pair for ValMusic before
publishing signed updater artifacts:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.tauri" | Out-Null
cargo tauri signer generate -w "$env:USERPROFILE\.tauri\valmusic.key"
```

Put the generated public key in `plugins.updater.pubkey` in `src-tauri/tauri.conf.json`. Add the
private key contents as the `TAURI_SIGNING_PRIVATE_KEY` GitHub Actions repository secret and,
if the key has a password, add `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` too. Keep the private key
out of Git. For a local signed build, set those same environment variables in the shell before
running the build. The key at `$env:USERPROFILE\.tauri\valmusic.key` is the release script's
default; its password can be left empty if the generated key has no password.

Tauri's updater requires this private key to sign the artifacts and its matching public key to
verify updates. If a public key is configured but `TAURI_SIGNING_PRIVATE_KEY` is missing, the
build prints “A public key has been found, but no private key.” Ordinary installer builds can
skip updater artifact generation, but then those releases cannot update through the app.
